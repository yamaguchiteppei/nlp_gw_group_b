# Slide Library（仮称）

PDF・PPTXをスライド単位で探し、過去資料の構成や表現を再利用するためのプラットフォーム。研究室での利用から始めるが、用途は研究発表に限定しない。

## 目的

人間が資料をファイル単位だけでなく**ページ単位で検索・閲覧**できるようにする。また、AIエージェントが同じスライド資産を検索し、過去資料を参考に実用的なスライドを作成するための検索基盤を構築する。まず人間向けのライブラリを実装し、エージェントによる検索と生成への連携を段階的に進める。

## 背景

過去のPPTXや、PPTXから変換してGoogle Driveに保管したPDFは、通常ファイル単位で管理されている。「研究背景を説明するページ」「モデル概要図」のようなページ単位の発見が難しい。Google Driveの「論文読み会」「言語処理学会」などのフォルダ階層も、検索・絞り込みに利用したい。

## 最初の目標

React/Vite・TypeScriptのフロントエンドとPythonのバックエンドで、**PDF・PPTXの登録、ページ単位の一覧・詳細表示と簡単な検索**を作る。画面はAPIを呼び、資料タイトル・著者・ページの見出し・概要の文字列、タグ、元フォルダで絞り込めるようにする。

Google Driveとの自動連携は後続段階で扱う。

## ローカルでの起動

Docker Composeでフロントエンドとバックエンドを起動する。

```bash
docker compose up --build
```

画面は `http://localhost:3000`、APIの接続確認は `http://localhost:3000/api/health`、API仕様の確認は `http://localhost:3000/api/docs` で行う。停止する場合は `docker compose down` を実行する。ホスト側に公開する開発用ポートは `127.0.0.1:3000` のみとする。現在のAPI実装は接続確認用のヘルスチェックのみである。

バックエンドのPython依存関係は `backend/pyproject.toml` と `backend/uv.lock` で管理し、コンテナのビルド時に `uv sync --locked` でインストールする。

## 機能の展開

| 段階 | 到達点 |
| --- | --- |
| 1. Slide Library | PDF・PPTXを登録し、ページを表示・保存・絞り込みできる |
| 2. Drive連携 | 元のフォルダ階層を保ってPDFを取り込める |
| 3. 検索拡張 | タグ候補・Embedding・画像特徴などを評価して追加する |
| 4. 生成連携 | 検索したスライドを参考に編集可能なPPTXを制作する |

デザイン比較機能は、必要に応じて追加する。
